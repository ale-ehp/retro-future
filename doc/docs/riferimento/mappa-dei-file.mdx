# Mappa dei file

La demo è `index.html` più la cartella `src/`, servita senza bundler: 102 moduli
JavaScript, 35 file di test accanto ai moduli che provano, un file di dichiarazioni
(`globali.d.ts`) e la libreria three.js copiata in `vendor/`. Le righe sono contate il
20 settembre 2026; cambiano a ogni commit, e questa pagina non insegue il numero
esatto ma la forma: quali cartelle esistono, cosa ci sta dentro, quanto pesa ognuna.

Le cartelle:

| cartella | cosa tiene |
|---|---|
| `src/` (radice) | `main.js`, che apre i sottosistemi nell'ordine giusto e li lega; `ctx.js`; `lingua.js`; i test trasversali (invarianti, ordine di boot e frame, importmap, scorciatoie di console) |
| `src/engine/` | post-processing, ciclo dei frame, prewarm, diagnostica, benchmark, shader, ispezione |
| `src/world/` | boulevard, palazzi, ponti, LED, tabelloni, pavimento a esagoni, cielo, rivelo, terminale |
| `src/character/` | modelli, animazione, folla, percorsi, chi accoglie, cartelli, passi, riflessi |
| `src/camera/` | stato del giocatore, mouse look, volo del drone, cursore, collisioni della camera |
| `src/controls/` | pannello di regia, controlli dal vivo, tastiera, movimento, mobile, copertina |
| `src/audio/` | contesto audio, colonna sonora, passi |
| `src/config/` | costanti pure |

## I file citati altrove nel manuale

Le pagine di questo manuale citano la fonte di ogni affermazione, e non tutte le fonti
stanno dentro la cartella della demo. Tre categorie, che non si aprono allo stesso modo.

**Il codice della demo.** `index.html`, `src/`, `test/`, `vendor/`, gli asset e questo
manuale sono l'intero contenuto del repository pubblico su
[github.com/ale-ehp/retro-future](https://github.com/ale-ehp/retro-future). Ogni percorso
che comincia per `src/` o `vendor/` si apre da lì.

**Gli attrezzi di qualità e di pubblicazione.** Il typecheck, il rilevatore di codice
morto, il gate visivo, il build e il Worker che serve la pagina stanno fuori dalla
cartella della demo, accanto al resto del sito che la ospita: servono a pubblicare, non a
disegnare la scena. Nel repository pubblico gli stessi controlli vivono sotto `tools/`,
adattati a girare da soli.

**I documenti di lavoro.** Le schede dei fatti, le verifiche incrociate, la guida di
stile e i prompt delle tappe di risanamento non sono pubblicati. Compaiono nelle colonne
“fonte e data” perché ogni numero di questo manuale deve essere tracciabile a qualcosa di
scritto, non perché il lettore possa aprirli. Dove una fonte è un documento interno, il
numero è comunque verificabile sul codice: la colonna dice anche con quale comando è
stato misurato.
